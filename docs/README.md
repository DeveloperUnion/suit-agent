# docs

**1 つの話題は 1 ファイルにしか置かない。**同じことを 2 箇所に書くと、片方だけが古くなる。

| ファイル | 役割 | 境界 |
|---|---|---|
| `../README.md` | プロダクトの仕様と決め事 | **いまどう動くか。**やること・やらないことの判断もここ |
| `database.md` | DB の実装 | **いまどうなっているか。**起動手順・CI・migration 一覧・踏んだ罠 |
| `database-design.md` | DB 設計の判断 | **なぜその形か。**RLS・提案→適用・fact_labels などの理由 |
| `todo.md` | **未完了のものすべて** | **これからやること。**他のファイルには書かない |
| `cost.md` | 運用費 | **いくらかかるか。**単価・内訳・上振れ要因 |

やり残しを見つけたら `todo.md` に書く。`README.md` や `database.md` に
「[ ] まだ」と書き足さない — 散ると全体像が見えなくなる。

## リポジトリに入れていない資料

クライアントから提供された資料と、社内で作成した打ち合わせ用の文書は
**このリポジトリに含めていない**。`private/` に置き、`.gitignore` で除外している。

| ファイル | 内容 |
|---|---|
| `private/採寸データ.jpg` | 実物の採寸票。**顧客の氏名と身体寸法が写っているため、リポジトリに入れない** |
| `private/要件定義書.md` | 要件定義書（ER図・画面構成・開発フェーズ） |
| `private/ヒアリングリスト.md` | 次回ヒアリングの質問リスト |
| `private/logo.png` | ロゴの原本。アプリが使う複製は `public/logo.png` |

`lib/constants/` のマスタ（採寸項目・補正コード）と
`lib/types/index.ts` のコメントは `private/採寸データ.jpg` を参照している。
手元に無い場合は、コードのコメントに転記の根拠と判読が不確かな箇所を残してあるので、
そちらを参照すること。

**要件定義書は人数まわりだけ古い。**「システム利用スタッフ 2〜3 名」とあるが、
実際は **10 名**（`cost.md` はこちらを前提にしている）。
